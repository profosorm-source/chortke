# چک‌لیست بررسی تغییرات (PR Checklist) — چرتکه

تمام توسعه‌دهندگان باید قبل از ارسال Pull Request یا ثبت تغییرات در برنچ اصلی، این چک‌لیست را به طور کامل بررسی و رعایت کنند.

---

## 🟩 بررسی‌های امنیتی
- [ ] هیچ ورودی از سمت کاربر به طور مستقیم درون دستورات SQL قرار نگرفته است (جلوگیری از SQL Injection).
- [ ] متدهای دانلود فایل از نظر الحاق نام فایل و هدرهای تزریقی امن شده‌اند (جلوگیری از Header Injection).
- [ ] متغیرهای خروجی در لایه HTML/View با انکودرهای مناسب فیلتر شده‌اند (جلوگیری از XSS).
- [ ] اطلاعات حساس مانند کلیدهای API و رمزهای عبور خارج از کدبیس و در فایل `.env` نگهداری می‌شوند.

## 🟦 بررسی‌های معماری و ساختاری
- [ ] تمام سرویس‌های جدید یا تغییریافته از کلاس پایه `\App\Services\BaseService` ارث‌بری می‌کنند.
- [ ] تمام کنترلرهای جدید از `BaseController` یا `BaseUserController` ارث‌بری دارند.
- [ ] برای حل وابستگی‌ها از تزریق سازنده (Constructor Injection) یا هلوپر استاندارد `app()` استفاده شده است و از `Container::getInstance()` در لایه‌های مدل یا هلپر استفاده نشده است.
- [ ] منطق تجاری سیستم (Business Logic) کاملاً از لایه کنترلر تفکیک شده و به لایه سرویس منتقل گردیده است.

## 🟨 بررسی‌های عملکردی
- [ ] کدهای طولانی و سنگین (مانند حلقه‌های محاسباتی پردازش دسته‌ای روی تراکنش‌ها یا کاربران) به صورت آسنکرون و از طریق سیستم صف (Queue) زمان‌بندی شده‌اند.
- [ ] کوئری‌های دیتابیس برای بهینه‌سازی و حل مشکل N+1 بررسی شده‌اند و از اتصالات اضافه خودداری گردیده است.

## 🟧 استانداردهای کدنویسی و تمیزی
- [ ] استاندارد نام‌گذاری کلاس‌ها (PascalCase) و متدها (camelCase) به درستی رعایت شده است.
- [ ] طول متدهای جدید تحت هیچ شرایطی از ۳۰ خط فراتر نمی‌رود و کدهای طولانی به متدهای کوچک‌تر شکسته شده‌اند.
- [ ] کدهای موقت، دستورات دیباگ مانند `var_dump`, `print_r` یا `dd` به طور کامل حذف شده‌اند.
